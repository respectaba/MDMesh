# Qualified configuration support projection

`GET /rest/private/agent/v1/devices/{number}/configurationSupport` uses the existing authenticated customer/device boundary. It returns only a source heartbeat, reported lock-task state (`kioskActive`) and up to six allowlisted control tokens. It does not expose raw capabilities, telemetry, locations or device credentials. Lock-task activity does not establish launcher mode; the Android appearance handler checks the stored mode and current authority at mutation time.

The projection reads one `device_state` row. A new nullable `configurationCapabilities` column stores only the control tokens reported in that same check-in. A single PostgreSQL statement updates the legacy command advertisement and complete state snapshot together. A state-less check-in invalidates the qualified snapshot atomically while retaining ordinary legacy command gating. A state with no capability frame stores an unavailable snapshot. Legacy rows are not backfilled from `devices.agentCapabilities`.

The additive Liquibase changeset is `26.10.21-configuration-capability-snapshot`. Actual serving provider column definitions were read before preparing it; no hosted change has been applied. Keep the column on runtime rollback. Old agents and the production installer are unchanged. The native platform separately verifies exact code-qualified agent identity, fresh ownership, company/device scope, the reviewed plan and current physical binding.
